# Riel Linux 1.0.1

Stable Linux x86-64 maintenance release with the bundled .NET runtime and native editor suite.

## Launcher and saved games

- Consist scans parse each resolved locomotive file once per scan, sharing its display metadata
  across repeated references. A new scan reads source files again and discovers new consists.
  This reduces repeated locomotive reads on HDDs without introducing a persistent source cache.
  Full route scanning remains; startup time still depends on the installed content and disk.
- Saved-game ZIP import/export runs outside the UI thread and supports cancellation. Imports
  validate entries, reject conflicts and stage files before publishing a save; failures roll
  back newly published files. Failed exports leave the previous archive intact.
- Imported saves retain archived timestamps. File operations and metadata reads are serialized,
  busy actions are blocked, invalid-save actions refresh correctly, and action buttons fit the
  saved-games window at its minimum width.
- Includes the English launcher, route/train information, clear Play and Tools buttons and
  seven selectable accent colors introduced in 1.0.0.

## Simulation and graphics

- Bounds water-trough traversal through repeated and zero-length track sections while
  preserving the existing within-section boundaries and directions.
- Reserves process-memory headroom for optional texture preloading and rechecks available
  space before each pending texture. This is not a GPU VRAM budget.
- Keeps all live aliases when marking shared textures, materials and shapes, and schedules
  resource cleanup after stationary train changes as well as tile changes.
- Builds instanced scenery from its authored LODs and chooses detail for each group. Groups
  use spatial cells and shape types to avoid combining widely separated or different objects.
- Updates MessagePack to 3.1.9 and System.Security.Cryptography.Pkcs to 8.0.2.
- Preserves physics formulas, simulation update frequencies and the saved-game format.
  Existing nearby-train retention, shader camera snapshots and MSTS track placement fixes
  remain included.

## Validation

Publication requires managed regression tests, shader validation/rebuild, self-contained
application publishing, native content-path tests, editor UI/OpenGL smoke checks and
portable-package checks without an installed .NET runtime. Launcher validation renders
119 interface previews.

New scan regressions cover 200 references across 100 consists sharing one locomotive parse,
updated locomotive metadata and newly added consists on the next scan, missing/cabless
engines and distinct engine files. Other regressions cover save-pack safety and cancellation,
saved-game action state, water-trough traversal, texture budgets, shared resource marking,
stationary cleanup and instanced LOD selection.

HDD startup times and FPS on the user's custom route and NVIDIA GPU have not been measured.

## Downloads

Extract the complete `riel-linux-x64.zip` archive and run `./riel gui` from its directory.
The ZIP includes the .NET and editor runtimes; the .NET SDK is not required to play.
The release also includes the ZIP's SHA-256 checksum and matching editor source archive.
Routes and rolling stock are installed separately and retain their authors' licenses.

## Compatibility and known limitations

- Linux x86-64 requires an OpenGL 3.3 driver and the desktop libraries documented in
  [INSTALL.md](https://github.com/agustinluzardo/Riel-Linux/blob/v1.0.1/docs/linux/INSTALL.md).
  Vulkan through Mesa Zink remains experimental.
- Older saves, especially those predating the public assembly rename, are not fully
  verified. Third-party add-ons built against `FreeTrainSimulator.*` require rebuilding
  against `Riel.*`.
- Linux multiplayer remains unvalidated. A complete timetable restore-to-viewer gameplay
  session is not covered by the headless saved-game tests.
- Existing route-content differences remain, including the FCGR signal between Quilmes
  and Ezpeleta that can appear green while the route treats it as red.
- Confirmation of previously reported visual problems on affected custom routes and GPUs
  remains pending. Custom-route FPS improvements have not been measured.
